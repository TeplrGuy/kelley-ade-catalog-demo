Reference Architecture

Key Components

Catalog Repository

GitHub or Azure Repos hosting environment definitions, templates, and documentation.

Environment Definitions

YAML files describing infrastructure patterns (web app, API, database, etc.).

IaC Templates (Bicep)

Reusable Azure infrastructure templates with built-in governance controls.

Azure Dev Center

Syncs catalog and provides self-service portal for app teams.

Managed Identity & RBAC

Secure, least-privilege access for deployments and compliance auditing.

Why This Architecture Works

Single Source of Truth

All infrastructure standards live in one catalog repository with version control.

Template Reuse

One approved pattern deployed across unlimited app teams and projects.

Automated Compliance

Governance, tags, RBAC, and audit logging built into every deployment.

Low Infrastructure Burden

App teams don't write Terraform. Platform team owns and evolves templates.

GitHub + Azure Interop

Catalog works with GitHub or Azure Repos, aligning with existing developer workflow.

Recommended Pilot Approach

1

Design One Environment Pattern

Start with a simple, high-demand pattern (e.g., web app + storage). Keep it focused.

2

Publish to Catalog Repository

Add environment definition, Bicep template, and documentation to GitHub or Azure Repos.

3

Connect to Azure Dev Center

Sync catalog into ADE and verify app teams see the environment in the portal.

4

Onboard Pilot App Team

Have one trusted app team self-service the environment. Collect feedback on DX.

5

Iterate & Validate Governance

Verify RBAC, approvals, and compliance. Refine template based on learnings.

6

Scale to More Teams & Patterns

Expand to additional app teams and new environment patterns based on demand.

Timeline: A well-designed pilot can go from concept to production validation in 4–6 weeks with part-time platform team effort.
